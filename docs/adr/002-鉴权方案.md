# ADR-002 鉴权方案

- 状态：提议（项目启动会讨论后改为"已采纳"）
- 日期：2026-10-12
- 决策人：D
- 相关需求：REQ-D-01、REQ-D-02

## 背景

所有服务都需要识别用户和权限；管理员可以新建角色（任务书附件 1）；服务之间也要互相调用。课程项目时间有限，鉴权应简单可靠。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 每次请求回调 common 校验 session | 权限实时生效 | common 成为单点；每次请求多一次网络调用 |
| B. JWT RS256，common 持私钥，各服务取公钥 | 服务被攻破也无法伪造 token | 需要分发公钥、实现 JWKS |
| C. JWT HS256，共享密钥，各服务本地校验 | 实现最简单，无额外调用 | 任一服务泄露密钥即可伪造 token；权限变更要等 token 过期 |
| 服务间：mTLS / 服务 JWT / 每服务一个密钥 + 白名单 | | mTLS 与服务 JWT 配置成本高 |

## 决定

用户鉴权采用 C：HS256，有效期 8 小时，不做 refresh token。token 中包含权限码，服务按权限码判断（`require_perm`），不按角色名判断，以支持管理员新建角色。

服务间采用每个服务一个密钥 + 被调用方白名单（`require_service`）。

数据库层：每个服务一个数据库角色，只拥有自己的 schema。

## 后果

- 权限变更最长 8 小时后生效，已记入风险清单。
- 密钥不进入仓库：未配置时部署脚本在服务器上生成随机值并保留，也可以通过 GitHub 环境 secrets 指定（ADR-011）。
- 若后续需要更强隔离，可迁移到方案 B，接口层（`CurrentUser`、`require_perm`）不变。
