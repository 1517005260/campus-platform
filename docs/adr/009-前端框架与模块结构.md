# ADR-009 前端框架与模块结构

- 状态：提议（项目启动会讨论后改为"已采纳"）
- 日期：2026-10-15
- 决策人：B
- 相关需求：所有需要界面的需求

## 背景

三个模块组要并行开发各自的页面，同时又要共用登录、权限、布局和请求层。任务书对前端技术不作限制，学生端可以是 Web 应用。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 每个模块一个独立前端工程（微前端或多站点） | 完全隔离 | 登录、布局、请求层要做三遍或抽成库；部署多个站点；6 人项目成本过高 |
| B. 一个 Vue 3 工程，按模块分目录，模块通过清单接入 | 共用基础设施；目录隔离足以避免冲突；一个镜像 | 需要约定好 core 与模块的边界 |
| C. 一个工程，页面平铺不分模块 | 最简单 | 三组人改同一批文件，评审和冲突难管理 |
| 框架：Vue 3 + Element Plus / React + Ant Design | 两者都适合后台管理类界面 | Vue 中文资料更多，组内更熟 |

## 决定

采用 B，框架 Vue 3 + TypeScript + Vite + Element Plus。接口类型从 `contracts/openapi` 自动生成（openapi-typescript + openapi-fetch），让契约检查覆盖到前端。前端模块目录与后端服务同名。

## 后果

- CODEOWNERS 按 `frontend/src/modules/<模块>/` 分配给对应模块组，core 归 B。
- 后端接口变更会导致前端编译失败，这是有意的：改契约必须同步改前端。
- 暂不做前端单元测试，CI 只做 lint、类型检查、构建；后续如需要可加 Vitest。
