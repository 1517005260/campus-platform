# ADR-006 占用与个人预约冲突时的处理

- 状态：提议（项目启动会讨论后改为"已采纳"）
- 日期：2026-10-12
- 决策人：A、C、E 共同确认
- 相关需求：INT-04

## 背景

教室被 M2 占用或 M3 下架时，时段内可能已有学生的个人预约。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 自动取消冲突预约，通知学生，不记违约 | 占用总能成功；学生被告知 | 学生计划被打乱 |
| B. 有冲突时拒绝占用 | 不影响学生 | 维修无法开始；整室申请几乎不可能通过 |
| C. 为学生自动改约到其他教室同类座位 | 体验最好 | 实现复杂；可能找不到合适座位 |

## 决定

采用 A。M1 在 `POST /internal/v1/blocks` 的同一事务中取消冲突预约（`cancel_reason = BLOCKED_BY_M2 / BLOCKED_BY_M3`），不写违约，经通知服务告知学生，并在返回值中列出被取消的预约。

## 后果

- 学生没有过错，不记违约，这一点也记入伦理记录。
- 方案 C 作为后续改进。
