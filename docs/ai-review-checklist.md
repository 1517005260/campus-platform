# AI 生成代码审查清单

维护人：D。评审 AI 参与编写的改动时逐项检查；同类问题出现两次，把对应规则补进 `AGENTS.md`，并在本清单记录来源 PR。PR 模板中的"人工验证"一节引用本清单。

## 公共能力与边界

- [ ] 使用了公共库已有的能力（根 `AGENTS.md`"公共函数优先"），没有在模块内重新实现 worker、种子、参数、跨模块调用、重试、测试 fixture
- [ ] 只访问本服务的 schema；需要其他模块的数据时通过 `campus_common.clients` 或消息
- [ ] 座位状态只由 M1 写入，并记录来源（`source`、`ref_id`）

## 正确性

- [ ] 时间一律带时区（`timeutil.now()`、`at_hour()`、`AwareDatetime`），没有 `datetime.now()` / `utcnow()`
- [ ] 权限用权限码（`require_perm`），没有比较角色名
- [ ] 状态迁移写成带状态条件的更新或乐观锁，并发下只有一方成功；能用数据库约束表达的规则放在数据库
- [ ] 需要 M1 配合的变更：先调远端、成功后再提交本地；补偿逻辑不会撤销并发成功一方的结果
- [ ] 服务间写操作带固定格式的幂等键，重试安全
- [ ] 通知与审计通过 outbox 发消息，与业务数据同一事务；没有直接 HTTP 调用 common 写通知
- [ ] 异步路由中没有阻塞调用（同步会话、`requests`、`time.sleep`、CPU 密集计算）
- [ ] 错误用 `AppError` 与大写下划线错误码，并写进路由 docstring

## 数据与契约

- [ ] schema 变更有迁移脚本，遵循"先扩展后收缩"；`alembic check` 无差异；种子幂等
- [ ] 改了接口或消息模型后运行了 `make contracts`，跨模块变更只做向后兼容的修改

## 测试

- [ ] 测试验证行为而不是常量或桩数据；没有 mock 被测函数本身
- [ ] 覆盖边界两侧（例如恰好到期、上限减一）与重复执行
- [ ] 故意改坏实现后测试失败，并在 PR 中写明改了什么

## 安全与隐私

- [ ] 接口与日志不返回密码哈希、token、密钥；没有把密钥写进代码或提交
- [ ] 返回给调用方的数据只包含必要字段（参见 `docs/ethics-log.md` 中关于学生信息的讨论）
