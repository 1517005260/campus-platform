# M1 后端实现边界

## 职责范围

M1 后端负责教室、开放时间和座位主数据，以及座位在各时段是否可预约。个人预约、取消、签到、提醒、未签到取消、完成、违约、系统参数和运营统计也由 M1 负责。

M1 是座位可用状态的唯一写入方。M2 和 M3 通过内部接口请求占用或释放教室，不直接访问 M1 数据库。

前端页面、登录与权限实现、通知渠道、M2 审批状态机和 M3 工单状态机不属于 M1 后端范围。

## 可用性规则

座位可预约必须同时满足：

- 教室和座位均已启用。
- 用户满足教室的院系限制。
- 预约时段完全位于开放时间内。
- 没有状态为 `booked` 或 `checked_in` 的重叠预约。
- 没有未释放且与预约时段重叠的整室占用。
- 整室占用没有结束时间时，视为无限期占用。

搜索、可用性查询和创建预约使用同一套判断，避免查询结果与预约结果不一致。

## 预约与签到

- 预约以整点小时为单位，时段为左闭右开。
- 相邻时段允许，重叠时段禁止。
- 单次时长由系统参数控制。
- 过去时段不能预约。
- 签到从预约开始前 15 分钟开始。
- 签到在到达 `start_at + auto_cancel_min` 时结束。
- 到达截止时刻后，未签到扫描可以取消预约。
- 签到和未签到扫描通过带状态条件的更新保证只有一方成功。
- 每个教室每天一个签到码，同一天重复查询返回同一个码。

## 状态追溯

`seat_status_logs` 记录座位可用性变化：

- 创建预约记为 `reserved`。
- 用户取消、未签到和占用取消记为 `released`。
- 管理员停用、M2 占用和 M3 维修下架记为 `blocked`。
- 管理员重新启用、M2 释放和 M3 恢复记为 `unblocked`。

签到只改变预约状态，不改变座位占用状态，因此不额外写座位可用性日志。

## 违约规则

只有未签到记为违约。用户取消和被 M2、M3 取消均不记违约。同一个预约最多生成一条违约记录。

## 运营统计

- 利用率使用已签到预约小时数除以有效开放座位小时数。
- 有效开放座位小时数按开放时间和当前启用座位计算，并扣除整室占用时段。
- 违约率使用 `no_show / (no_show + completed)`，分母为 0 时返回 0。
- 按小时分布使用各整点有效签到座位小时数除以该整点有效开放座位小时数。
- 统计只返回聚合结果，不返回学生个人自习轨迹。

当前模型没有座位启用状态和开放时间的历史序列，因此历史统计只能按当前配置计算。需要精确还原历史时，应增加对应的时间序列数据。

## 伦理关注

- 每日签到码可能被暴力尝试或转交他人，需要后续评估错误次数限制和异常签到处理。
- 连续预约多个相邻时段可能绕过单次四小时限制，需要后续评估每日总时长或高峰配额。
- 自动取消和违约记录可能因签到设备或网络问题误判，需要保留通知、状态记录和后续申诉机制。
